# Proposal

## Why

Secure random generation is the foundation for salts, IVs, and keys used by every later namespace (encryption, key derivation, password hashing). Providing it first gives callers a safe CSPRNG now and removes any reason to reach for `Math.random`.

## What Changes

- Add the `random` namespace (`@jscv-solutions/node-crypto/random`) with three operations backed only by `node:crypto`:
  - `bytes(length, encoding?)` and `bytesSync(length, encoding?)`: `length` random bytes as a `Buffer` by default, or as `hex` / `base64` / `base64url` text when `encoding` is given.
  - `integer(options)` and `integerSync(options)`: bounded random integer from an options object `{ min?, max }` with `min` inclusive and `max` exclusive (mirrors `node:crypto` `randomInt`; `min` defaults to `0`).
  - `uuid()`: version 4 UUID string from `node:crypto` `randomUUID`, synchronous only.
- Enforce strict validation: non-integer or negative `length`, empty or unsafe integer ranges (`min >= max`, non-safe-integers), and unsupported `encoding` values throw `NodeCryptoError` with code `INVALID_ARGUMENT` and messages that never echo generated bytes.
- Note an intentional, narrow exception to `shared-core` variant parity: `bytes` and `integer` have async plus `Sync` variants with equal results and errors, while `uuid` is sync-only because `node:crypto` `randomUUID` is synchronous and an async wrapper adds no value (DEVELOPMENT_PLAN says "`Sync` where meaningful").
- No new dependencies. No hand-rolled primitives. Never use `Math.random`.

## Capabilities

### New Capabilities

- `random`: secure random bytes, bounded integers, and UUIDs including validation, error codes, and sync/async parity rules.

### Modified Capabilities

- None.

## Impact

- Affected code: `src/packages/random/` (replaces the repository-tooling placeholder), `src/packages/random/typings/` declarations consumed via `import type`, `tests/` mirrors for the new runtime modules.
- Public API: new `random` subpath export only; no changes to existing exports.
- Dependencies, build, release: none. No breaking changes. Out of scope: `comparison`, `digest`, `message-authentication`, `password-hashing`, `key-derivation`, and `encryption` namespaces, plus the docs site beyond JSDoc for the new functions.
